## Notion에서 반영한 정책과 남은 경계

같은 상품·같은 출발일의 **결제 완료 인원**을 합산한다. 옵션이 달라도 함께 모집하며 취소된 시연 신청은 집계에서 제외한다. 인원이 먼저 모여도 출발 확정은 D−7 모집 마감일에 표시한다. 마감 때 최소 인원 미달이면 여행 취소 상태를 보여 준다.

허니문은 2~10명 중 짝수 인원으로 신청하고 커플마다 2인 차량을 제공한다. 일반 최소 3명 조건을 커플 단위에 맞춰 **최소 2커플(4명)**로 해석했다. 다른 테마는 최소 3명이다. 신청 대표자와 모든 동행자의 성명·주소·연락처를 받는 시연을 구성했다.

현재 날짜 경계는 브라우저 날짜의 D−7 당일부터 신규 신청·고객 취소를 제한한다. 정확한 마감 시각·시간대와 D−7 당일 포함 여부, 인원 미달 취소 시 자동 환불·알림 처리는 운영 정책과 서버 작업으로 확정해야 한다. C05의 ‘모집 마감일 기준’은 표시 상태를 확인하는 시연이며 실제 시간·신청 상태를 변경하지 않는다.

가격·옵션 단위와 하향 변경 허용, 단골 산정 기준·할인율, 직원 초대·승인·등급 수정 권한, 신청 이후 구성 변경은 미확정이다. 시연 가격은 1인 샘플 금액이며 단골 할인은 임의로 만들지 않는다.

## 검증 현황 — 현재 v0.8

최종 `npm run build`, `npm run lint`, `git diff --check`를 통과했다. 다음 항목은 이번 버전에서 직접 확인한 결과다.

- Liquid Glass 전역 재질 연결 후 홈(`/`), 여행 목록(`/tours`), 상품 상세(`/tours/bali`), 로그인(`/login`)을 데스크톱 브라우저에서 다시 확인했다. 헤더·검색·필터·상품 카드·예약 패널·입력과 버튼의 글자 대비와 조작 영역이 유지된다. 배포 CSS는 104.07KB/gzip 22.50KB이며 실제 셰이더 청크는 20.16KB/gzip 5.42KB로 홈 검색에서만 지연 로드된다.
- 기본 1280×720 및 900×800 홈에서 문서 너비·높이가 화면 크기와 일치한다. 320×780 홈도 한 화면 안에 로고·테마 소개·모델·검색·테마/모션 조작이 들어간다. 짧은 모바일에서는 내용 보호를 위해 일부 세로 스크롤을 허용한다.
- 허니문·효도·골프·트레킹의 실제 모델, 효도 온천/부모님/정자/차량, 골프 페어웨이/벙커/카트/클럽, 트레킹 능선/숲/출렁다리/스카프를 시각 확인했다. 하나의 Canvas를 유지하며 전환하고 정지 상태에서도 모델을 유지한다.
- 홈 검색의 효도·2026-11-20·2명·교토 조건 → 목록 1건 → 상세 → 구성 → 신청 화면 연결과 조건 전달을 확인했다. 390px에서도 동일 흐름을 진행했다.
- 고객 시연 진입 직후 빈 여행 내역 팝업과 닫은 뒤 신청 화면 복귀를 확인했다. 예시 신청자·모든 동행자를 채우고 2,580,000원 결제의 처리 중 비활성화 → 실패 안내 → 입력 유지·재시도 → DEMO 신청 상세를 확인했다.
- 결제 완료/출발 대기/문자 미발송이 별도 상태로 표시된다. 모집 마감일 기준에서 2명/최소 3명은 여행 취소, 고객 취소 버튼 비활성으로 바뀌는 것을 확인했다. 오늘 기준 취소 시 0명 집계·환불 시연 상태 및 내 여행의 취소 내역을 확인했다.
- 고객 시연 계정의 직원 접근 차단, 직원 시연 진입, 상품 목록/등록/등급·제한 입력을 확인했다. 재고 입고는 변경 전후 24→30개 및 목록 반영을 확인했다. 320px 직원 표·상품 등록 폼은 페이지 가로 넘침이 없고 표 영역만 내부 스크롤한다.
- 이전 음성 문장 검색 흐름은 제거했다. 현재 UI는 마이크 입력 크기만 보여주는 파형이며 브라우저 실제 마이크 권한은 이번 변경에서 테스트하지 않았다.
- 계산 검증은 허니문 짝수 인원·커플별 차량 수·프리미엄 샴페인 중복 방지, 같은 상품/날짜의 옵션 무관 결제 집계·취소 제외·날짜 분리, D−7 경계·인원 미달 취소, 잘못된 달력 날짜, 목록 가격 정렬·빈 검색을 통과했다. 직원 날짜/정수/재고 합산/옵션 제한/연락처 검증도 통과했다.
- 개인정보·DEMO 신청·계정 정보는 메모리에만 유지한다. localStorage에는 장바구니와 여행 구성을 저장하며 역할 변경·시연 종료 시 개인정보와 신청 내역을 지운다.

미저장 편집의 기본 브라우저 확인창이 검증 도구 입력을 차단했다. 해당 구현은 화면 안의 확인 dialog로 교체했고 고유 제목 ID·Escape 취소·입력 유지·포커스 복귀를 코드로 확인했다. **교체한 이탈 확인창과 이용 안내 팝업의 최종 브라우저 조작은 미검증**이며, 남아 있는 이전 확인창을 사용자가 취소한 뒤 재확인할 수 있다.

실제 마이크 허용/거부, OS reduced-motion 전환, WebGL 강제 실패, 저장 공간 차단, 전체 키보드 순회·실기기 GPU 성능은 실행하지 않았다. 실제 인증·API·결제·문자·자동 환불은 미연동이다. 수집한 새 탭 콘솔에는 실제 오류가 없고 R3F가 사용하는 `THREE.Clock`의 upstream deprecation 경고가 남는다. 홈↔목록 3회 왕복에서 Canvas 수가 홈 2개·목록 0개로 반복 복원됐다. 홈 3D 지연 청크는 **949.72KB / gzip 255.95KB**이고 Vite 500KB 청크 경고도 남는다. 경고 기준을 올려 숨기지 않았다.

## 다음 연결 단계

1. 가격·옵션·단골·직원 권한·D−7 경계를 확정하고 서버 DTO를 UI 모델과 분리한다.
2. 상품·출발 일정·회원·이력 API를 기존 `api/client.ts`와 도메인 함수에 연결한다. 요청 로딩·오류·재시도·세션 만료 후 복귀를 실제 응답으로 처리한다.
3. 예약 스냅샷과 최종 가격을 서버에서 검증한다. 결제 제공자와 idempotency, 모집 집계·마감 작업·문자 결과·취소/환불을 연결한다.
4. 직원 인증·서버 권한 검사, 상품 버전·재고 동시 수정·고객 접근 범위·등급 계산과 변경 이력을 연결한다.
5. 자체 상품 사진과 최적화 로고 자산을 준비하고 3D 모델별 비용·캐시·모바일 성능을 측정한다.

리뷰·지도·별도 추천 챗봇은 이번 필수 범위에 추가하지 않는다. 기존 관심상품 기능은 장바구니로 전환했다.
